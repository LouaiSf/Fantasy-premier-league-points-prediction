## Slice A: Chip Advisor rebuild (contract v4)

### Implemented

- **A1 Account sync.** `webapp/fpl_client.py` gained `get_history()` (parses `entry/{id}/history/`: `chips[]` and `current[]`). `webapp/manager_status.py` (new, pandas-free) holds two pure functions: `derive_chip_inventory(chips, current_gw)` (splits played chips into `first_half`/`second_half`, marks an unplayed first-half chip `expired` once GW19 passes, tracks `last_free_hit_gameweek`) and `derive_free_transfers(current, chips, next_gw)` (replays the 2026/27 FT rules -- GW1 unlimited, +1/week capped at 5, a chip week spends no FT and still banks one). Wired to `GET /api/managers/<id>/status` in `manager_routes.py`. The Chips page auto-syncs this once per imported manager (`syncFromFpl` in `app/chips/page.tsx`), shows "Synced from FPL · GW<n>", and any manual edit (chip toggle, Free Hit GW field, free-transfers input) flips a `local_user_reported` flag that sticks until the manager clicks "Re-sync from FPL". `StoredSquad.freeTransfers`/`freeTransfersSource` (app-provider) are shared with Transfer Studio (not yet consumed there -- see Not done).
- **A2 Projection matrix.** New `scripts/chip_engine.py` owns the chip engine; `optimise.py` re-exports `compute_chips`/`build_point_matrix`/etc. at the bottom of the file (after its own solver functions exist), and `chip_engine.py` never imports `optimise` at module load time -- every call goes through a lazy `_optimise()` that also prefers whichever module identity (`optimise` vs `scripts.optimise`) is already in `sys.modules`, so a test that monkeypatches one spelling is never silently shadowed by the other. `build_point_matrix(players, future_points, fixtures, first_gw, last_gw)` uses covered weeks as exported (hard `i/u/s/n` status zeroes only the *current* gameweek, not the whole matrix); an uncovered week is `per_fixture_xp x fixtures_that_week x (1 + FDR_SLOPE*(3-avg_fdr))`, clipped at 0. The global fixture-signal fallback for squads is gone: `model_projection` mode now requires only a complete 15-man squad and at least one real covered gameweek anywhere in the export; `fixture_signal` mode is reserved for "no complete squad".
- **A3 Comparable gains.** `solve_squad`/`solve_squad_horizon` gained `owned_indices` + `max_changes` (a "keep at least N-of-M owned" inequality, distinct from the existing exact-count `must_transfer_out`) and `time_limit_seconds`/`gap_rel` (CBC `PULP_CBC_CMD(timeLimit=, gapRel=)`). `load_horizon()` now returns a 4-tuple (`players, points, p_plays, gameweeks`) -- `p_plays` pivots the export's own column (DGW takes the max of the two fixtures), default 1.0 when the column is absent; all 4 call sites (webapp, CLI, `chip_advice`) updated. Per chip: **TC** = best captain's points (unchanged). **BB** = bench total minus `_expected_autosub_points` (GK: `(1-p_start_gk)*bench_gk_xp`; outfield: `m = sum(1-p_plays)` over starters, bench slot k gets `clip(m-(k-1), 0, 1) * xp`). **FH** = unrestricted one-week `solve_squad` total minus `solve_squad(owned_indices=squad, max_changes=FT)` (FT = synced/entered for the current week, 1 for every future week). **WC** = `solve_squad_horizon` unlimited over a fixed 6-week window (`WILDCARD_WINDOW`, never the UI horizon; truncated near GW38 and flagged) minus the same horizon with `max_changes=min(15, FT+5)`.
- **A4 Joint plan.** `_candidate_window` unchanged in spirit but now takes `last_gw` (always through GW38) instead of a UI `horizon`. `chip_policy.py` replaced `ChipDecisionPolicy` with `ChipPlanPolicy` (`MIN_GAIN` per chip, `CLOSE_CALL_MARGIN=1.0`, `FUTURE_RELIABILITY=0.95`, `WILDCARD_WINDOW=6`). `_joint_plan` brute-forces every unused chip's (week-or-hold) combination (≤4 chips x ≤~19 weeks + "hold" each) maximising total discounted gain with no two chips sharing a gameweek -- cheap once gains are computed, no MILP. Status is `play_now` (assigned = now and gain ≥ `MIN_GAIN[chip]`) / `planned` (assigned = a future week) / `hold` / `unavailable` (used or expired in *every* half -- a chip merely used in the current half still has a next-half copy) / `no_squad` (fixture-only mode), plus two independent flags `close_call` (`|discounted best-other-week - gain_now| < 1.0`) and `use_or_lose` (`remaining eligible weeks this half <= unused chips this half`). Contract version bumped to 4; `fixture_signal_index`/`raw_signal`/`alternatives`/`runner_up_gameweek` are gone from the response, replaced by `chip_plan`, `week_states`, `gains_by_week` per chip, `free_transfers_used`.
- **Performance.** A naive full-season, all-candidate-week evaluation of the real GW6 squad (14 candidate weeks in the first half, ~487-player market) measured **55s cold** -- WC's per-week 6-week-horizon solves dominated, exactly as the plan warned. Two changes brought it to **~8s cold, ~0s warm**: (1) `_reduced_market()` restricts FH/WC's full-market solves to each position's top 25 players by total projected points over the window plus its 6 cheapest (budget enablers), always keeping every owned player -- verified on live GW6 data that the optimum is unchanged down to a 15+4 cut, so 25+6 keeps a wide margin (one week's Free Hit optimum did move by about 1 point at the 25+6 cut, which is within the model's own stated error); (2) the per-candidate-week loop runs on a `ThreadPoolExecutor` (CBC solves are external subprocesses via `pulp.PULP_CBC_CMD`, which release the GIL while waiting) -- verified correct (identical output with 1 vs many workers) and safe for concurrent use (`pulp`'s `LpSolver_CMD.create_tmp_files` uses a fresh `uuid4()` per solve). `webapp/app.py` also added a small in-process LRU (`_CHIPS_CACHE`, 16 entries) keyed on everything that changes the plan *except* the display-only `horizon`, confirmed to make a horizon toggle return instantly with an identical `chip_plan`.
- **A5 Chips page.** Horizon `<select>` removed; the header now has a `My squad | Fixtures only` segmented control, disabled with "Needs 15 players (you have N)" when the squad is short, driven by the local squad rather than a request round-trip. New `chip-plan-timeline.tsx`: a horizontally-scrolling GW-by-GW strip from now to GW38 with a gold divider at GW20, hatched cells for `extrapolated` weeks, DGW/BGW badges, and a chip icon on each assigned week. The four chip cards show status pill (+ a "Close call" suffix), assigned GW, "Now X vs best +Y", a `BarStrip` of that chip's gain across every eligible week (states `now`/`best`/default), the plan sentence, and a `Why this choice` disclosure rewritten for the new evidence shapes (bench list, FH's one-week XI, WC's window/truncation). `chip-opportunity-matrix.tsx` is now the "gain heatmap" (chip x eligible GW, in points, the assigned cell outlined) rather than the old mixed-units fixture-index matrix; "Fixture context" (the FDR table) stays as a separate section with `projection_state` relabelled to the v4 vocabulary (`Projected`/`Extrapolated`/`No fixtures`/`Complete`/`No confirmed fixtures`). `lib/types.ts`/`lib/chips-contract.ts` rewritten for contract v4.
- **A6 Tests.** `tests/test_chip_advisor.py` rewritten (28 tests): direct unit tests for `_candidate_window`, `build_point_matrix` (covered/extrapolated/blank/hard-status), `_expected_autosub_points` (full gain at p=1, reduced gain with uncertain starters), `_no_chip_total` (FT=2 baseline beats FT=1), and integration tests reproducing the plan's own TC GW6-vs-GW16 (`play_now`, not `close_call`) and GW6-vs-GW7 (`close_call`) worked examples, horizon-independence of the full `chip_plan` and of Wildcard's `gains_by_week` across horizons 4/8/12/16, the joint plan never double-booking a gameweek and honouring a pre-scheduled chip, DGW/blank-GW evidence, selling-price-vs-market-value budgeting, and the export-shorter-than-the-half extrapolation case. `tests/test_optimise.py` and `tests/test_webapp.py`'s chip-contract tests updated for the new `load_horizon` 4-tuple and the v4 field names/status vocabulary. Full suite: 321 passed.

Deferred -- would need a small backend addition, not a frontend-only fix.
